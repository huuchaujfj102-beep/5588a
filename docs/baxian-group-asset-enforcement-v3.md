## 强制生产流程，禁止跳过

1. **资产目录准备**：把本人已批准原始PNG、法宝PNG放入 `--asset-root`，文件名严格按 `film_audit/assets/baxian_source_authority_v2_20261107.json`。GitHub当前只有元数据，没有全部原图二进制；缺原图时必须BLOCK，不得伪称图像已被模型绑定。
2. **单人素材分层**：先由已批准主图提取人物及道具（不重画五官），每人角色层、法宝层、对应遮罩；透明RGBA且与背景画布同尺寸。抠图产生的小范围边缘修补要单独登记改动区域及溯源。**现有RG​​BA层的哈希不代表它一定与原图像素相同**，仍须局部原图对照和人工验证。
3. **位置锁定**：先固定四前四后与白仙驴倒骑，角色朝向与镜头机位同时记录。
4. **生成前执行 gate**：检查可用原始文件、来源SHA、每人角色/法宝层、遮罩、法宝数/归属、布局、尺寸/风向及脚本模式；任何P0直接返回 `BLOCKED`。
5. **只合成背景和正确前景层**：不允许再把八人全合图送入文本生图作为身份重画；必要的角色动作转向需要独立重建候选并经审核后再加入锁层。
6. **生成后执行 gate**：除重新校验全部来源/锁层外，验收生成图SHA、七个岗位证据、12个视觉分类逐条PASS以及 P0=P1=0；**这一步人工逐图检查不可由SHA自动代替**。
7. **只有 `READY_FOR_USER_REVIEW` 才提交用户看**；用户明确确认版本和hash后另行记录 `USER_APPROVED_FINAL`。新关键帧尚未经批准时不得覆盖旧定版母图，不得直接投入正式I2V。
8. **失败后一次性整改**：聚合所有缺陷Issue IDs，标原图、区域、根因、修改说明、禁止变化部分、回归检查，先完成 PRE-GEN QA，不准无策略反复整图重生成。

## 机器能做与不能做
代码已执行**结构性校验**：来源文件及SHA、角色人数、道具数/分配、图层、遮罩、世界站位、审核证据是否齐全。它**没有部署人脸比对/人体姿势估计模型**，不能自动证明面容一致、驴蹄落地自然、浪花物理真实、全片无穿帮；这些必须由实际出图后审核记录证明。


## V3 实际分层合成入口（不重画人物）

在已经具有**真实**的8人物、8套法宝独立RGBA图层及遮罩，且V3预检通过后，可执行：

```bash
python -m pip install 'Pillow>=11.0,<13.0'
python -m film_audit.baxian_layered_composite \
  --plan film_audit/shots/s04_01_layered_group_plan_TEMPLATE.json \
  --asset-root ./private_baxian_assets \
  --report ./baxian-composite-report.json
```

程序只执行像素分层叠加：先放受SHA锁定的海岸背景，再后排4人、前排4人，法宝层按固定前后遮挡关系绘制。角色图层RGBA彩色像素不经过文字AI重画，也不允许覆盖批准原图文件；若缺透明图层、遮罩为空或整个画布不透明、图层SHA漂移、目标文件已存在，直接终止。生成图自动命名/记录为 `CANDIDATE_RENDERED_NOT_APPROVED`，后续仍需七岗位和八人逐人复核。

**逐人终审进一步加严：** `review.actor_checks.BX01…BX08` 每人分别记录 identity / face / hair / wardrobe / prop_shape_count / anatomy / ground_contact 共7项PASS，以及独立存在的证据图文件；不允许共用同一张审核证据伪装成八人分别检查。任何一位FAIL，都阻断READY_FOR_USER_REVIEW。定版权属于用户本人，程序永不自行标最终批准。

**局限**：此合成程序不提供自动人像抠图或自动改动作；没有本地已批准角色RGBA前景时，它不会自造出“相似”的人物。对于新动作/新角度，要先通过独立制图＋用户审核形成合法新层。它也没有真实人脸像素对应检验、接地物理视觉分析或模型级拦截器；外部生图工具若绕开该专用入口，仍可能生成错误图。因此八仙项目必须统一经过本入口及其强制审核，不将其他工具返回的原始整幅生成图直接纳入母图库。
