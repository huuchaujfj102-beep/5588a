# 《八仙·大显神通》R6｜20章逐章制作与验收规则 V1.0

生效日期：2026-11-22。适用20章40段全片。规则写入不代表实际生成或验收。

## 逐章强制流水线

1. 剧本核对：逐章核对R6完整剧本、前章结尾与后章开头、人物动机、对白、动作因果、情绪和地理轴线。不得把已有图片串联视作剧情完整。

2. 分镜规划：按动作意图而非固定秒数拆镜；逐镜确定时长、景别、首中尾帧、动作节拍、声音桥和跨章接点。镜头数不等于新增图片数。

3. 原始资产审计：打开实际已批准PNG，核验SHA256、原生像素、人物五官服饰、法器道具、场景地形、机位、风雨潮向和时序。原图只读，不覆盖。

4. 逐镜缺口：每镜标记REUSE_ORIGINAL、CROP_SAME_SOURCE、I2V_ONLY、NEW_KEYFRAME_REQUIRED或HOLD_REFERENCE；说明新增图承担的独立叙事信息，避免重复生图。

5. 参考图真实绑定：新图生成时必须实际输入批准母图像素，保存文件ID、SHA、模型请求与输入证据。文字提示‘参考母图’不算绑定；无证据标记BLOCKED_REFERENCE_UNBOUND。

6. 静帧逐张生成与验收：按小批次逐张核对A-L（身份人数、剧情顺序、道具归属、接触承重、视线轴线、光影环境、质感、时序物理、画幅像素、原生参数、参考绑定、邻镜连续性）。失败图隔离整改，用户明确‘过’只记录导演静帧认可，不替代技术通过。

7. 图生视频：技术和导演静帧双通过后，按动作完整性、首尾帧、口音声线、口型、声画同步、风雨潮向、物理与声桥生成；实际视频逐段审查。未生成不得标VIDEO_PASS。

8. 整章验收：检查叙事完整、片长节奏、角色弧光、道具连续、场景地理、声音、动态接缝和下一章起点；阻断项清零、视频实际通过、导演确认后才可CHAPTER_LOCKED。

9. 下一章准入：第N章未CHAPTER_LOCKED不得宣称第N+1章正式制作完成；可提前盘点跨章母图与衔接但不可跳过验收。继承地点、天气、潮位、浪向、人物站位衣装伤势和道具状态。

10. 可追溯归档：每章独立保存剧本版本、镜头表、图片哈希、真实参考输入日志、生成参数、技术审核、导演审批、成片与跨章接点；GitHub工作分支，原图不覆盖。

## 状态门禁

SCRIPT_CHECKED → SHOT_LEDGER_READY → ASSETS_AUDITED → GAP_LIST_LOCKED → REFERENCE_BOUND → STILLS_TECH_PASS → STILLS_DIRECTOR_APPROVED → I2V_RENDERED → VIDEO_QC_PASS → CHAPTER_LOCKED → NEXT_CHAPTER。任一项失败退回整改，不越级。

## 必填台账字段

chapter_id, scene_id, shot_id, story_beat, dialogue, voice_accent, timing_seconds, source_file_id, source_sha256, character_master, prop_master, scene_master, reference_actually_sent, model_request_id, output_sha256, native_resolution, frame_role, action_phase, previous_end, next_start, review_A_L, technical_status, director_status, i2v_status, chapter_gate。未知填UNKNOWN。

## 补充强制规则 V1.1｜每次出图后立即严格检查（2026-11-24）

**适用全片20章、所有图片生成和精修；与前述第3、5、6、10条及状态门禁并行生效。**

1. **生成前准入**：先查正式镜号、上一镜批准帧、人物/道具/场景母图的原始像素与路径，列出本镜唯一动作目标及禁止改变区。若母图文件无法读取、实际参考输入未被确认，或故事动作与上一镜重复，标记 `BLOCKED_PRECHECK`，不得假称严格锁定或直接批量生成。
2. **一张一检**：每次仅生成一张独立原生9:16关键帧。图像工具返回后**当轮立即审查**，不能仅显示图后结束，也不能将审查推到下一次用户催促。禁止多格拼图、横幅裁切冒充原生竖图。
3. **生成后九项必检**：①主体身份/脸型/发型/服装/人数；②专属道具与接触点；③母图建筑、船只、海堤、石门及透视几何；④动作是否真正推进且与前镜不重复；⑤绳结、拉力、浮力、水流及接触物理；⑥镜头轴线、方向、潮位、风雨光影和昼夜连续；⑦手部、肢体、穿模、拓扑/文字/水印；⑧实际像素、宽高比、单幅性；⑨实际母图输入证据和上下游镜头衔接。
4. **三类明确结果**：`TECH_PASS` = 全部关键项有依据通过；`HOLD_REPAIR` = 存在待修、未核实或母图未绑定；`REJECT` = 明确换脸换装、主体换型、违反镜头意图、重复镜头、错误比例或重大物理错误。不得将“基本像”“风格接近”写作严格通过。
5. **每图固定输出质检报告**：必须附镜号/名称、对应母图和上一镜、九项逐项结果、可见差异、是否重复、最终结论、入库状态、下一步精修范围。无法查验的事项写 `UNKNOWN`，不得猜测通过。
6. **未通过不得自动流转**：`HOLD_REPAIR`/`REJECT` 立即拦截下一镜批量制作；只修失败项，保护已通过区域。技术未过不得写 `STILLS_TECH_PASS` 或以“合格”入技术库。
7. **导演明确审批与技术状态分别保存**：用户说“过”可记 `DIRECTOR_APPROVED` 并依其要求登记，但不能抹去技术风险或伪造参考绑定；台账记录导演批准日期、技术异议及后续I2V风险。
8. **复检可追溯**：保留原始母图只读；记录输入/输出路径、SHA256、模型请求ID（若有）、失败原因、修复项、复检结论与版本，不能以新文件覆盖批准母图。
9. **连续性断言**：一张画面与上一张若没有新的可见动作（如“呼喊→解缆→绳圈脱桩→船离岸”每步应可辨），哪怕风格精美也判 `REJECT_DUPLICATE_BEAT`。分镜编号按事件顺序登记，不以每次生成自动递增。
10. **本规则实例**：最近“缆绳脱离木桩、渔船离岸”候选图仍以渔民双手解缆为主，脱桩尚不明确，应列 `HOLD_REPAIR`；不得在未核实图片细节时宣布该动作已完成。

**质检标准输出格式**：镜号｜动作意图｜原母图｜参考实际输入｜人物｜道具｜空间｜物理｜时序｜画幅｜图像缺陷｜邻镜对照｜结论｜导演状态｜技术状态｜入库/阻断｜整改项。


## 补充强制规则 V1.2｜返工只修不合格区、已通过区冻结（2026-11-24）

1. **逐项分区冻结**：在任何返工前，把检查表中的每个“通过项”转换为PROTECTED（保护区），记录像素区域/人物特征/道具几何/位置/光影。所有未通过项列为EDIT_ONLY（允许修改区）。不得在修缆绳时擅自改脸、服装、船体、海堤和天气。
2. **最小差异优先**：优先对最新候选图执行明确的局部编辑/掩膜编辑；必须实际提供该候选及定型母图作为视觉参考。若工具无法证明局部冻结，标记UNVERIFIED_LOCK，不得宣称像素级“其他地方不变”。
3. **改错后的双向复核**：先确认所有原有“通过项”仍通过，再确认全部EDIT_ONLY失败项已经解决；任一通过项退化，整张REJECT_REGRESSION，不以修复局部掩盖其他返工。
4. **物理与剧情红线**：第一章“渔民放绳→空桩→船离岸”之后，下一镜应突出船已脱离岸边、自由端松垂/随船远离；严禁再让同一渔民双手拉紧一条仍连接船体的受力缆绳，不得重复此前拉绳/解绳动作。
5. **状态门禁**：TECH_PASS须完成通过项保护核对、失败项复检、母图参考绑定证据和相邻镜动作对照。导演“过”另行记录DIRECTOR_APPROVED，不擦除尚未解决的技术风险。每次出图后即时报告，未通过不上正式技术库。
6. **返工报告必填**：原候选及母图ID｜PROTECTED清单｜EDIT_ONLY清单｜实际输入参考证据｜修复前后差异｜通过项是否退化｜九项QC｜技术状态｜导演状态｜是否入库。

## 补充强制规则 V1.3｜第二遍生图双阶段锁定及回归验收（2026-11-24）

**本节优先于宽松的“基本通过”描述，适用全片20章及全部人物、道具、场景镜头。二遍图不是重新构思，而是针对一遍候选缺陷进行可审计的定点修复。**

1. **二遍前先分类**：把一遍九项质检逐项登记为 `PASS_LOCK`（通过，冻结）、`BASIC_PASS_LOCK`（基本通过，冻结可证实的造型、相对位置与风格，同时将尚未证实细节明确标为待核）、`FAIL_EDIT`（明确未过，必须修改）、`UNKNOWN_VERIFY`（待审核，必须验证，不能默认合格）。每一项附原图可见依据及对应镜号。
2. **通过项不得回退**：二遍仅允许对 `FAIL_EDIT` 和 `UNKNOWN_VERIFY` 进行最小局部编辑；已通过的角色脸、发型、衣装、道具、船型、海堤、建筑、色温、机位、画幅需锁定。一遍“基本通过”不能自动升级为完全合格，细节仍必须核实。
3. **严格图像参考绑定**：须以**当前获导演批准的一遍图**为直接编辑输入，同时实际绑定对应原始批准母图与邻镜。只写文字“完全不变”无效。模型或当前工具无法提供掩膜/主体像素锁定时，真实记录 `LOCK_NOT_GUARANTEED`，严禁称为逐像素一致。
4. **负面硬约束**：禁止全幅重新设计、换脸、换服装、换船、换法器、换景、换地理轴线、额外人物或旗帜、拼图、凭空更换受力绳路；不允许用画质提升掩盖叙事或几何错误。
5. **先复验旧通过项，再验新修复项**：二遍生成后先逐项确认 `PASS_LOCK` 和 `BASIC_PASS_LOCK` 保持，任何回退均判 `REJECT_REGRESSION`；然后对每一条 `FAIL_EDIT` 和 `UNKNOWN_VERIFY` 给出证据及结果。尚有任一阻断项即 `HOLD_REPAIR`，不能宣称“全部通过”。
6. **动作阶段与绳路校验**：每镜必须能与前后镜区分动作意图。第一章“解缆→脱桩→放船→船向深水漂移”各自独立；二遍“漂移渔船”图须以船为构图主体、岸上渔民仅次要甚至不出现、空桩不再与船相连，船位与海岸距离/海流方向清楚。
7. **严格产出与状态**：一次只生成一张原生9:16；出图同轮立即给出九项QC和一遍/二遍差异表，记录输入源路径、源SHA、输出SHA、模型请求ID/未知值、导演状态与技术状态。用户“过”可作 `DIRECTOR_APPROVED`，不能清除技术缺陷。
8. **入库条件**：关键失败项全部实际修复、原有通过项零回退、母图输入证据完整，并通过邻镜因果连续性校验方为 `SECOND_PASS_TECH_PASS`；否则只保留二遍候选，不覆盖批准原图，禁止自动进入下一镜。

**当前镜头 V1.3 实例**：上一张获导演“过”的《暴雨港湾中的漂流渔船》一遍图，保护其9:16、蓝红旧渔船、破帆、港湾石堤、冷蓝暴雨与暖灯；二遍仅校准船作为主体、与岸间距增大、流场拖向外海、移除重复的岸上渔民特写。船体几何或空间无法精确复核时，记录技术待核，不得伪称二遍已全项通过。


## 补充强制规则 V1.4｜第二、三遍生图：状态归类、定点整改、零回退验收（2026-11-24）

**本规则覆盖V1.2/V1.3中第二遍、第三遍的执行细节，适用全片20章及所有静帧。导演审批状态与技术验收状态必须分开。**

### A. 必须整改的触发状态（不得跳过）

凡检测记录出现 **“未证实”“未达标”“有局部变化”“待审核”“待核验”“待修”“不通过”“未达到严格锁定证据标准”**，都转成 `REPAIR_REQUIRED`。先逐项与原始批准母图、上一遍图、前后镜头进行实际对照，列明差异、需编辑区域与验收证据；不能凭“看起来接近”直接改成通过。无法取得母图/真实图像绑定时记 `BLOCKED_REFERENCE_UNBOUND`，不能虚报已修复。

### B. 必须保护的状态（零回退）

凡记录为 **“通过”“基本通过”“已经修正”“已经消除”“外观基本保留”** 的具体可见元素，一律登记 `PROTECTED_LOCK`，在第二遍和第三遍中保护不变。特别注意，“基本通过/外观基本保留”只冻结已经观察到的合格特征，尚未证实的微细节单独列 `REPAIR_REQUIRED`，不得以模糊标签掩盖未证实项。

保护要素包括但不限于：人物脸型/五官/发型/衣装/姿态，渔船型制/蓝红色船体/破帆/舱灯，道具，海堤与渔村布局，气候/光照，镜头轴线，9:16独立构图和已通过动作节点。禁止为了修一处而重绘已通过区。

### C. 二遍生图强制流程

1. 输入：一遍候选图 + 原始批准定型母图 + 上一已批准镜头，记录真实输入文件、SHA和可用的模型/编辑证据。
2. 建立 `PROTECTED_LOCK` 与 `REPAIR_REQUIRED` 两张清单，明确每个待修点的目标、编辑区域、前后镜头因果。
3. 优先局部掩膜/区域编辑，只对 `REPAIR_REQUIRED` 改动，原始母图只读；如工具不能保证像素级冻结，明示 `LOCK_NOT_GUARANTEED`，不得称“其他地方完全不变”。
4. 生成后**先审核保护区有没有回退，再审核待修项是否真正变为有证据的通过**；任何保护区退化标 `REJECT_REGRESSION`，任何未证实/局部变化仍残留标 `HOLD_REPAIR`。
5. 全部关键项通过且参考绑定与镜头连续性证据完整才标 `SECOND_PASS_TECH_PASS`，否则不得当作技术合格或自动进入下一镜。

### D. 三遍生图强制流程

1. 只有二遍仍存在 `REPAIR_REQUIRED`、`HOLD_REPAIR` 或 `REJECT_REGRESSION` 时，启动第三遍；不得仅为提高漂亮程度而整体重绘。
2. 三遍的 `PROTECTED_LOCK` = 第一遍、第二遍中已确认通过/基本通过/已修正/已消除/外观基本保留的**全部已核实特征之并集**；任何已完成的修正不得复发。
3. 三遍的允许编辑区域 = 二遍尚未证实、未达标、有局部变化及其他失败项的**最小范围**。每一项先对照原始母图与二遍图列差异，再实施局部修复。
4. 三遍出图后双向回归：复查一遍和二遍已通过区、再复查三遍整改区；一处退化或残留未核实，即不得标 `THIRD_PASS_TECH_PASS`。
5. 若依赖的图像工具不能实现真实的参考绑定或保护区锁定，停止声称“已全部修复”，标记 `BLOCKED_LOCK_PROOF` 并报告技术限制；不得无限生成近似图凑次数。

### E. 本镜头的立即执行清单

《第一章·渔船被回流拖向深水区》二遍图：
- `REPAIR_REQUIRED`：①船体几何完全锁定**未证实**；②原海堤与建筑布局**有局部变化**；③通过区域完全保持不变**未达严格锁定证据标准**。
- `PROTECTED_LOCK`：独立9:16；蓝红旧船、破帆、暖舱灯的已观察到外观；渔船成为画面主体；重复渔民动作**已消除**；空桩不再束缚渔船**已修正**；船离岸与海浪关系中已证实的部分。
- 应先核对原始 F01-C02/F01-04 和一、二遍图；仅修上述阻断项。若保护区改变，判回退；若任一“未证实/有局部变化”未解决，保持 `HOLD_REPAIR`。
