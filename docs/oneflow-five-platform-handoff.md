# OneFlow 五平台一条视频交接（2026-11-03）

## 本版本实际完成的功能

运行现有 `.github/workflows/qianfan-i2v-oneflow.yml` 的一个人工入口：
- 一句话 brief → Cloudflare 首帧（需要有效的已授权免费配额）→ 一次明确批准的百度 MuseSteamer 5 秒图生视频（可能计费）
- 下载原始视频 → FFmpeg 原创合成音效、动态「造镜者」水印 → 视频技术 QC
- 只有成功生成 `AWAITING_HUMAN_REVIEW` 的视频且 MP4 哈希匹配 `qc.json` 时，创建 `delivery-kit/report.json` 和 5 个 `delivery-kit/<platform>.json`：
  - `douyin` 抖音
  - `kuaishou` 快手
  - `xiaohongshu` 小红书
  - `shipinhao` 视频号
  - `youtube` YouTube

交付包包括标题、简述、目标画幅、视频校验哈希、授权审核和平台回执状态。所有平台状态初始为 **NOT_SUBMITTED**。没有合规 API 投稿或人工回执之前，绝不宣称 `published`。

## 仍需完成的事情

1. **生成方面**：当前 MuseSteamer API 只处理一条五秒片段。15/30 秒三段或多段递进生成、首尾帧连贯与物理一致性，仍需单独实现和付费验收。
2. **画幅方面**：目标平台的 9:16 建议不代表模型原生输出 9:16；若源片为正方形，不能将加黑边的视频宣称为原生竖屏。需重新构图或适配并审核。
3. **发布方面**：仅抖音具有受 OAuth 权限和人工确认约束的官方 API 投稿模块。快手、小红书、视频号、YouTube 目前仅生成待上传的编辑交接包；接入应依照各自当前开放权限和官方流程执行，不能用未获准的抓包或浏览器自动化绕过审核。
4. **隐私方面**：5588a 是公开仓库，Actions 输入/工件可能公开。不得将私密素材、账号令牌、患者内容或尚未公开的商业素材送入公开工作流。应迁移至私有运行空间。
5. **运营闭环**：没有官方视频 ID、平台可见性状态和数据回执前，播放/订单/收益应保持未知值，不得填模拟数字。

## 验收标准

- `python -m unittest discover -s tests -p 'test_oneflow_distribution.py' -v`：确保一条视频生成五份交接资料，视频被篡改或任务仍在等待时不得假装发布。
- 无新模型 API 调用进行测试；真实生成仍显式由 `confirm_paid` 控制。
- 保持 `.github/workflows/oneflow-douyin-reviewed-publish.yml` 独立的人工批准和 OAuth 入口，禁止在生产工作流自动公开发布。
