# 《基准帧锁帧防跑偏规范》V2.0｜古装仿真人影视剧通用实操分步教程

版本：V2.0｜更新：2026-11-11｜类别：**古装仿真人（电影级真人写实风格）图生视频通用标准**。适用历史剧、宋韵/唐风/明清叙事、武侠、权谋、古装悬疑、古风情感、古装奇幻等；适配支持图生视频的 Seedance、Vidu、千帆等模型，**时长、画幅、参考图数量、负面栏是否支持，均以实际版本接口能力为准**。本文件是规范，**不代表已通过所有平台真实视频测试**。

## 0. 核心原则、定义与优先级

**一场戏的固定空间和角色身份，由获批的静态主基准帧（MASTER_ANCHOR）及角色/道具母图共同确定；每段均关联并在模型能力允许时实际挂载主帧。禁止仅以上一段末帧作为唯一身份与场景参考滚动接力。**

- **人物定型母图**：同一演员/角色面容、骨相、肤色、年龄、发型、胡须、妆容、服饰多角度；需批准版本和原文件哈希。
- **道具/服化母图**：器物形制、材质、磨损、大小、朝向、佩戴点、数量；衣领、腰带、袖口、层次、刺绣、鞋履、发饰、假发固定。
- **主基准帧**：一场戏、一处空间、一个稳定的机位族的静态世界蓝图，冻结人物初始站位、镜头轴线、空间结构、布景、光照、时间天气、道具初始状态。不同空间/时间或根本性场景变化应另建主基准帧。
- **子基准帧**：有审批记录的同场景新机位、合法动作阶段、新表情、道具状态或局部构图变化；必须指向父主帧与批准资产，不可暗中改动原始母图。
- **末帧**：用于动作状态与剪辑接续的弱参考；若模型不支持双图，保留线下对照，绝不谎称已上传双参考。

优先级：**获批人物/道具/服化资产 > 审核通过主基准帧 > 审批子基准帧 > 剧本状态表 > 末帧弱参考 > 文本提示词**。主帧若包含与人物母图冲突的错误，必须先修复主帧，不能把错误“永久锁定”。

## 1. 第一步：建立并审核静态主基准帧（只定稿一次）

1. 准备角色卡、多视角图（正面/三分之四/侧面/背面等）、服装分层图、道具形制图、场景平面图、机位图与分镜；缺关键参考标 `PENDING`，不得直接生成“最终片”。
2. 建立真实空间关系：`scene_id, anchor_id, period_style, location, time_of_day, weather, actor_ids, prop_ids, blocking_map, camera_side, lens, key_light, practical_lights`。
3. 生成或合成**一张稳定的写实主帧**，统一古装时代材质与生活质感：真实皮肤毛孔/皱纹、自然发际线、丝麻棉缎布料、合理衣物重量和褶皱、实体木石陶铜玉质感；非用户指定不加仙气/超自然元素。
4. **三道静态审核**：
   - 门禁A **人物身份与服化妆**：同一面容、眼距、发际线、年龄、神态基线、胡须发髻、衣料色彩、内外衣层次、饰件和鞋靴，必须与批准母图对应；人数和左右顺序正确。
   - 门禁B **道具与场景**：茶盏、兵器、书卷、酒壶、桌椅、门窗、屏风、牌匾、道路、山水等形制/数量/归属/相对位置稳定；道具与时代风格相容；环境拓扑合理。
   - 门禁C **物理关系与镜头**：十指与器物真实接触、重心和脚底落点成立、视线与对手演员对位、光影方向/反射一致、180°戏剧轴明确、景深透视统一。
5. 建立**空间锁定表**：人物头/脚/手、主要道具中心与包围框、门窗与地标用归一化画面坐标 `[0,1]` 保存；人物/道具真实相对位置用世界关系表记录。**推镜必然造成屏幕坐标变化，不能错误地把“坐标逐像素恒定”当成正常运镜合格条件。**
6. 通过后冻结不可修改母图 `MASTER_{scene_id}_v01.png`，存 `SHA-256`、原始分辨率、审批人员及日期、对应资产清单。比例适配使用另存无裁切副本，SHA 单独记录；禁止由视频压缩截图替换原主帧。

## 2. 第二步：每个视频片段的固定开单流程

1. 选择 `image-to-video`，绑定本场戏主帧；如果当前镜头与主帧静态动作不同，先审批子基准帧并同时记录主帧父级关系。**模型只能输入一张图时，优先使用最接近当前镜位的获批基准帧；主帧仍在项目层强制对照，但不能声称实际双图输入。**
2. 设置参数：`model={实际型号}`、`duration={模型实际支持的秒数}`、`aspect={分镜审批比例}`、`resolution={实际返回分辨率}`。常用 5–12秒分段、16:9或9:16，仅是生产建议，不是固定产品能力承诺；需要12秒时先验证模型版本是否支持。
3. 加载固定锁参块（见第6节）；每段只改 `台词`、`动作起止状态`、`单一主运镜` 和 `合法表情`。对白优先固定机位/极轻推镜；武戏需分动作关键姿态建子帧，不以一句长提示驱动多阶段复杂打斗。
4. 逐项比对：演员及服装、道具物主与数量、手握点、空间方位、180°轴侧、光源与反打轴、分镜声音/口型、上段动作状态。没有新增道具或人物，除非该镜头经批准。
5. **生成前 PRE_GEN Gate**：输入文件存在及哈希匹配；三道静态门禁均有证据；本镜机位/人物/道具/动作状态一致；参考图实际绑定能力已核验；账号额度和付费授权符合要求。任一P0 `BLOCKED`；无法视觉检查写 `MANUAL_REVIEW`，不冒充PASS。
6. 提交单次任务，保存 `run_id, model, seed(if supported), references_actually_used, anchor_sha256, segment_id, prompt_version, duration_requested/actual, width/height, cost, provider_status, output_uri`。失败先查状态，禁止未知结果盲目重试导致重复扣费。

## 3. 第三步：多段拍摄、动作接续及强制回锚

- **每一段都绑定场景主帧身份和空间规则；每3段额外执行一次跨段回锚巡检。** 例如第1/2/3段分别审，第3段结束对比主帧；第4段不得只用第3段的末帧开拍。
- **方案A｜慢节奏古装对白**：用本镜批准的主帧/子帧单参考，末帧做离线对照；最适合席间对谈、书房议事、庭院交流。
- **方案B｜动作连续性增强**：模型确实支持且已验证双参考时，主锚强参考+上一段末帧弱参考；权重调节仅在产品支持时配置。末帧不可凌驾身份锚；双图不支持则降级A。
- 每段记录角色状态：坐/立、左/右手持物、杯中液位、袖摆朝向、书卷开合、佩刀入鞘状态、前后移动、眼神与情绪起止；连续动作承接的是**状态表**，不把已经漂移的坏末帧当下一段唯一基准。
- 切换昼夜、空间、妆发/换装、完整新机位：新建或审批**独立主帧/子帧**。越轴需要明确新的建立镜头与审批，而不是隐藏切换。

## 4. 第四步：输出逐段审片与失败回滚

每段抽检：首帧、每秒代表帧、所有手物接触峰值、台词发音瞬间、动作突变点、末帧及相邻段交界；三段后集中对照主帧。
- **P0致命**：换脸/体型年龄突变；服化完全换样；角色左右错位或未授权越轴；关键道具易主/复制/消失；刀剑出入鞘状态错；十指严重畸形；杯具漂浮/穿模；布景重构；超出剧本的额外人物/物品。任一出现 `BLOCKED`，失败段禁止接力和入库。
- **P1严重**：发簪或衣襟变动、胡须头发微漂、嘴唇与对白明显不同步、轻度穿模、光色方向跳变、服饰局部纹样变化、反打视线错位。退回局部修复或重跑该段。
- **P2瑕疵**：轻微颗粒、可后期修正的边缘闪烁或局部噪点。修复并保留证据。
- **自动/人工边界**：静态主帧使用SHA逐字节锁定；运动视频经相机运动/透视补偿后比对身份、环境和道具轨迹，**不应要求运动画面逐像素等于原帧**。可用“补偿后的静态锚点偏差≤画面对角线1%、手物接触漂移≤器物宽度5%”作为**待实测校准的候选指标**，不是通用保证值或已部署算法。
- 失败闭环：`BLOCKED → 定位问题秒数与区域 → 确定母图/子帧/提示词/模型根因 → 仅修局部静态候选 → 三道预检 → 重跑失败段 → 逐帧与跨段复验 → 放行`。不得改动已经通过的角色/道具区域，不得把整图重画称为局部精修。

## 5. 第五步：新增镜头与剧情元素的变更管理

新人物入场、角色起身/转身、掏出道具、饮茶、拔剑、推窗、风雨加强、反打/俯拍、表演情绪加重等，都须先确认剧本允许；有明显新姿态/道具状态/机位时**制作并审批静态子基准帧**。子帧带 `parent_anchor_sha256`、变更遮罩、合法变化范围、动作状态；原主帧和批准演员/道具图不覆盖。转场到新地点或新的时间天气条件，应使用新场景主锚。

## 7. 第六步：每镜头交付与库存替换门禁

输出：`manifest.json`、主帧及子帧 SHA、人物多视图ID、服化/道具ID、剧本状态表、空间与轴线图、实际生成模型/计费回执、首中末及问题帧、P0/P1/P2审核、人工核验及修复日志。状态仅允许 `PENDING / BLOCKED / READY_FOR_USER_REVIEW / USER_APPROVED_FINAL`。**用户未批准前，候选片不得覆盖母库，也不得自动发布**。

### 项目化覆盖方式
本文件只包含**古装仿真人通用基线**，不硬编码某个剧情、人物、法器、红日/仙鹤/陶罐或具体模型。项目特别规则应放在独立人物资产表与场景 profile 文件，以 `PROJECT_PROFILE` 对应本文字段；特别的魔法/仙术效果、木船海浪、雨雪天气等只在剧本授权时激活。现有《八仙过海》专属角色/法宝门禁仍由其项目规范独立管理，不被本通用标准替代。

**边界声明：规则能够减少跑偏风险，不能单靠提示词保证100%一致；必须验证真实输入是否被模型采用并检查真实输出。**
