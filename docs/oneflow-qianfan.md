# Baidu Qianfan ERNIE: one-sentence storyboard (opt-in)

Status: Adapter code and offline mock tests are included. A successful read-only
`GET /v2/models` authentication check does **not** prove paid text inference
or any image/video generation has been successfully run.

## What this does

- Calls official Qianfan V2 `POST https://qianfan.baidubce.com/v2/chat/completions`
  using `QIANFAN_API_KEY` as a Bearer credential from the environment.
- Selects an explicit text model; do **not** assume all listed models support
  text chat or are enabled for this particular account.
- Requests a structured JSON storyboard with exactly the required number of
  shots. Validates nonempty `prompt` and `sound` for every shot, then reuses
  existing `film_prompt` for the OneFlow seven-module prompt framework.
- Creates `storyboard.md` and `manifest.json` with provenance
  `qianfan_live:<model>`; it does **not** produce MP4 in story-only mode.
- Does not edit `main`, change the review gate, or connect media models.

## Billing and secure operation

This repository is **PUBLIC**. GitHub Actions inputs, logs, and artifacts
are not an appropriate destination for secret client briefs, private videos,
patient information or confidential reference assets.

Never commit `QIANFAN_API_KEY`. In a trusted **private** runtime, provide it
through a secret manager/environment. The repository's existing GitHub
Actions Secret `QIANFAN_API_KEY` was confirmed to support read-only
model listing; it cannot be displayed or extracted.

A text generation POST may incur Qianfan fees. It is **never** invoked by
`python -m oneflow run` without `--live-plan` or `--live` when the story
kind is `qianfan`. `--live-plan` is the recommended first paid test because
it excludes image, video, and audio generation.

### Offline tests (no API key and no network)

```bash
python -m unittest discover -s tests -v
```

### Optional text-only live test (explicit billing authorization)

Only after choosing an enabled Qianfan chat model and accepting its pricing:

1. Copy `oneflow/config.qianfan-story.example.json` to a local **untracked**
   private configuration file and replace `REPLACE_WITH_ENABLED_MODEL_ID`.
2. Configure `QIANFAN_API_KEY` in the trusted runtime (do not echo/print it).
3. Run:

```bash
python -m oneflow run \
  --prompt "原创15秒超跑短片：启动、疾驰、尾喷蓝焰，只有音效不要旁白" \
  --seconds 15 --ratio 9:16 \
  --config private-inputs/qianfan-story.json \
  --out private-inputs/oneflow-jobs \
  --live-plan
```

`--live-plan` makes **one** Qianfan chat request for all shots, not one
request per shot. The run fails on invalid model, missing Secret, malformed
JSON, or an API error; it does not silently fall back to heuristic.

To generate final media, separate image/video providers must be integrated
and validated first. Do not use `--live` on this text-only config; it will
refuse rendering because no image/video providers are present.

## Known boundaries

- No production inference has been charged or attempted by this PR.
- No Qianfan text-to-image or video generation adapter is enabled yet.
  These are separate endpoints and can have separate permissions/costs.
- No automatic posting to Douyin or other platforms is implemented.
- The provider response is schema-checked but the creative quality,
  vehicle/character consistency, rights and physical action still require
  review. Invalid JSON is an explicit failure (no unbounded retries).
- The adapter passes prompt text to Baidu on explicit live use. Never provide
  private or sensitive material without authorization.

## Manual GitHub Actions entry (available once reviewed and merged into main)

The workflow `.github/workflows/oneflow-qianfan-story.yml` is **manual only**.
It is not run automatically on push or pull requests. Visit GitHub Actions →
`Qianfan ERNIE storyboard manual test (opt-in billing)` → Run workflow.

- Choose a **text/chat** model that your Qianfan account actually supports.
  The prefilled `ernie-5.1` is an example, not a guarantee of access.
- Leave `confirm_paid_request=false`: the job makes **no API call**.
- Setting `confirm_paid_request=true` is explicit approval to submit exactly
  **one** paid text request using a fixed **public fictional supercar prompt**.
- The output storyboard is uploaded as a one-day GitHub Actions artifact.
  Because this is a **public repository**, do not insert private prompts.
- No images, video, audio or public posts are generated by this workflow.
- The workflow will not appear as a manual action in the repository's default
  Actions tab until a reviewed copy is merged to the default branch.
