# 文字成图规则 V2.0

适用：单幅关键帧、人物/场景/道具概念图及套图。与[图生视频规则](image-to-video-rules.md)分开执行；分类词表和足部细则复用[穿帮防控规则](image-video-continuity-rules.md)，不重复堆入每个请求。

## 生成前锁定

| 字段 | 必须明确的内容 |
| --- | --- |
| 本镜任务 | 单张图的唯一时刻、用途、景别、画幅和允许裁切线；特写不强求全身 |
| 角色 | 本镜可见人数、身份、服饰/发型版本、姿态、视线与左右手；不得把全故事人物都画进来 |
| 道具 | 名称、数量、部件、比例、轴线、持握、支撑、连接与遮挡；参考用途分开标注 |
| 场景 | 场景ID、门内外、人物前进方向、固定锚点、天气/时段、光源与相邻镜状态 |
| 允许变化 | 神通、漂浮、变形、残肢、特殊造型按本次设定保留；未批准细节不能自行当作锁定事实 |
| 文字/风格 | 保留用户要求的宋韵/CG/动漫/写实等风格；需要的招牌、字序、横竖方向、品牌水印逐项锁定 |

参考图缺失的背面、底面和隐藏部件登记待确认。不得为了“结构完整”扩出未批准部件；复杂道具优先露出能自洽验证的区域。

## 提示词组成

主体与本镜动作时刻 → 明确构图 → 道具结构与接触 → 场景方位 → 光影材质 → 输出规格 → 相关负面约束。只画一个时刻，不把先后动作拼成多手、多脚或多物件。

通用正面模板：

> 按本镜批准参考绘制，保持用户指定身份、服饰、风格、文字与画幅；只出现本镜可见人物及指定数量道具。部件轴线、连接、握持、支撑与遮挡合理；每只鞋一组鞋面和鞋底，无衣摆下额外鞋形，特殊肢体依角色设定。建筑透视、纹理、光源与反射一致。神通按明确设定呈现。关键元素在要求的构图范围内，留足边缘空间。

负面词分“基础结构＋相关道具专项”，使用共享编译器；不无条件禁止漂浮、变形、文字、logo、动漫、局部裁切或正常光影变化。否定道具和未入镜道具不应触发新增专项要求；文本识别只作保守辅助，复杂否定句仍需人工检查。

## 接口执行

- `compile_prompt(stage="image")` 输出最终正文、负面词、规则版本与模式；只替换自身终端规则块，重复编排不堆叠。
- HF/fal/Cloudflare现有适配器没有启用独立负面字段，因此把约束写入实际正文；OVH使用独立字段并与计划一致；原生千帆图片同样编入实际正文，不臆造API字段。
- 长度限制按仓库适配器的既有防护检查，不当作全球平台最新规格。先检查最终正文，空间不够时精简规则，但保留原文、相关专项及负面词；仍超限则在调用前拒绝并要求精简任务或拆镜。
- dry-run与正式调用使用同一编排与预算检查。记录`rule_version`、`prompt_chars`和负面传递方式；未发送不能写“已发送”。
- 不把提示词中的8K、UE5、35mm等当作实际输出参数或实测证据。

## 静态验收

先看全图人数、空间、姿态、构图，再放大脸、双手、脚、道具接口和遮挡边缘；与批准母图、相邻批准镜头比对。足部逐个数鞋面、鞋底、鞋尖和鞋跟，检查衣摆下第三只鞋及重复鞋底。局部修复后全项回归，防止修脚换手、修剑换衣。

多余肢体/鞋、道具断接、轴线错位、穿体、人数或物件增殖为阻断；遮挡证据不足为待核查，不凭想象判通过。只有静态合格且所需参考明确，才进入视频制作；生成成功和文件可解码不等于视觉验收。

# 图生视频规则 V2.0

适用：已批准首帧或参考资产转视频。先执行[文字成图验收](text-to-image-rules.md)，再沿用现有七模块，不另建重复流程。具体关键词复用[穿帮防控规则](image-video-continuity-rules.md)。

## 首帧与状态卡

记录首帧文件/版本/哈希、镜号、角色/服饰/道具/场景ID、本镜可见范围、前镜末状态、本镜初末状态、允许变化、动作起止窗口、光源与天气、机位/方向、输出规格和审查状态。没有批准首帧不应以技术可读代替批准；命令入口能读取文件也不等于已完成视觉签核。

项目专用规定优先于通用默认：如《望花楼》已批准的招牌简体“望花楼”、竖版方向、门内外机位、单段时长上限，均不得被泛化模板覆盖。历史云盘I2V模板与项目资产存在冲突时，先按已批准母图与项目主规则核对，不把较新时间戳自动等同于批准。

## 七模块要求

1. **原图锁定**：身份、服饰、道具数量、结构、连接点、构图和画风；允许动作改变投影与衣褶，不能冻结所有像素。
2. **局部微动**：只执行本镜要求，说明动作主体、关节链、幅度、节奏、起止和承重转移；多步骤按时间拆开。动作结束保持末状态，不回跳首帧。
3. **环境动态**：雪、烟、蒸汽、水、花瓣分别有来源；仅执行设定动态，附随衣料/发丝变化随动作合理产生。
4. **镜头运镜**：未指定时默认锁机；明确要求推、拉、横移或环绕时一次一主运镜，记录方向与幅度。慢速是默认建议，不覆盖用户明确的速度或固定镜头。
5. **光影动态**：主光源与时间状态连续；允许视角引起反射变化和明确剧情的灯火/昼夜变化，禁止无因闪变。
6. **画质参数**：时长、帧率、画幅、音轨按适配器支持设置并核对实际文件。神话题材不改成赛车，不擅自添加台词、加速或车辆。
7. **负面约束**：结构基础＋时序专项＋相关道具规则；禁止无解释的瞬移、消失、变形，不误伤明确神通；正常轮转、风动、流水不应被全部禁掉。

## 三种运镜复核

| 镜头 | 核对 |
| --- | --- |
| 慢推 | 主体比例连续、景物视差合理、纹理不撕裂；对焦按约定变化 |
| 横移 | 柱梁栏杆、门窗与道路保持结构；遮挡再显露不变款、不复制主体 |
| 环绕 | 首帧看不见的背面必须有参考或缩小幅度；道具轴线、握持、服饰与空间关系一致 |

## 执行与审片

`compile_prompt(stage="video")`在七模块、原生千帆视频和Vidu入口共用。不同入口重复经过编译器时只保留一份规则。最终文本超限先精简规则，仍不足在模型调用前报错，不截断原剧情。负面字段是否独立使用按适配器已实现能力，不新增未经核验字段。

先正常播放全段，再慢放接触/动作转折/遮挡再显露/切点，必要时逐帧。抽帧模型保持ADVISORY_ONLY，不得输出自动通过。首尾两个时刻增加下方细节裁片以帮助发现多鞋，但裁片不增加时间覆盖、不补足被遮挡信息，也不保证脚恰好位于裁片内；人物脚位不同或道具微小需人工选区查看原分辨率。

每条问题写镜号、版本、时间码或图片区域、可见证据、严重程度、不确定性和返修要求。无证据的遮挡归待核查；局部修复后复核相邻镜与全图。首尾通过不等于全片通过，逐帧检查必须真的逐帧执行。

## 剪辑与Remotion

Remotion负责合成而非模型负面词生成；用素材/时间线检查执行规则。核对入出点、镜长、帧率、缩放裁切、画幅、转场重叠、音画同步和水印文字。真实运镜变化与转场窗口内的有意融合不直接算穿帮；窗口外的残影、失真、无因状态跳变需返修。

当前仓库Remotion仍为独立测试片模块，不把它描述成已具备自动视觉穿帮检测。已有技术审核、人审与发布门禁继续保留。

# 生图与生视频穿帮防控：增补规则

本文件只补充已有七模块导演提示词、连续性约束和人工审核门禁缺少的细则；既有流程见 [OneFlow](oneflow.md) 和 [GLM文本审核](glm-runpod.md)。

## V2.0 接入范围与规则优先级

- 两套完整执行规则：[文字成图](text-to-image-rules.md)、[图生视频](image-to-video-rules.md)。本文件保留完整分类清单与专项判定，避免每次重复粘贴全文。
- 共享编译器 `oneflow/continuity_rules.py` 编排正面结构、负面约束和相关道具专项，版本2.0；七模块、共享生图、原生千帆图片/视频、Vidu入口均使用。
- HF/fal/Cloudflare负面约束进入实际prompt；OVH独立负面字段与计划一致。长度校验在模型调用前，dry-run与live一致，只精简规则、不截断用户原文。
- 优先级为用户本次明确要求、已批准项目资产与专项规则、通用默认。保留用户指定画幅、风格、文字、水印、动作与神通，不强制所有任务写实、竖图、全身或慢推。
- 不把“背负葫芦”误识别为背剑，不因倒骑就把坐骑改成驴；未入镜或明确否定的道具不应自动增加。复杂文本识别仍可能有歧义，需预检。
- 摄影的正常透视、遮挡、反射、景深变化不是穿帮；负面词应限制无解释错误。未指定镜头运动默认锁机。
- 可选模型审核取首尾两时刻及下方细节裁片，仍为建议，不能证明中间动作、全片或版权通过。Remotion按素材与时间线规则检查，不假设存在模型负面栏。
- 8K/UE5等属于视觉要求，实际技术参数按输出文件核验。

静态高频，动态为重点。

物体接触穿帮、手没有握住道具、手指穿插道具、手掌穿透物体、指尖与接触面无因分离、抓握姿态悬空、脚踩空、脚部穿透地面、接触阴影缺失或位置矛盾、衣物穿插道具、布料穿模、布料和物体互相穿透、饰品穿插皮肤、配饰无依托悬浮、腰带或飘带连接点缺失、发丝穿插物体、发丝穿插皮肤。

## 6. 镜头时序与运镜连贯穿帮清单

视频专项。

| 运镜 | 正面约束 | 必查项 |
| --- | --- | --- |
| Slow Push-in 慢推 | 单次低速连续推进，主体结构与相对位置稳定 | 背景层级与视差、门窗比例、纹理稳定、对焦渐变 |
| 横移 | 机位连续侧移，近远景视差与遮挡顺序合理 | 栏杆与柱数、道路连续、背景补全、物体无拖影复制 |
| 环绕 | 按约定方向与幅度连续转动，角色与道具三维结构一致 | 背面结构、握持点、剑鞘轴线、遮挡再显露、光影随视角合理变化 |

## 7. 可直接选用的提示词模块

### 正面基础约束

人物与道具数量明确且一致，完整合理的结构与比例，部件连接清楚，握持和支撑可信，接触点与遮挡关系正确；建筑与道路空间连续，透视一致；纹理附着表面，主辅光源和反射、阴影关系合理；人物、关键法器及必要的脚部完整入镜，边缘留出空间。神通效果严格按当前设定呈现，不改变主体结构。

### 静态基础负面词

## 足部专项：衣摆遮挡下的重复鞋形（新增）

1. 全图检查后，必须放大脚部复核；不能只数最明显的两只鞋。逐一标记鞋面、鞋底、鞋尖、鞋跟，搜索衣摆后方和左右边缘露出的额外鞋形。
2. 每只鞋只能有一组自洽的鞋面与鞋底；局部露出的鞋尖/鞋跟应可归属同一只脚，禁止第三只鞋、重复鞋底、双鞋尖融合及无腿来源的独立鞋形。普通单人按两足解剖关系核对；截肢、跛足、多角色或神话特殊肢体依明确设定处理，不强行补齐或删减。
3. 鞋子与衣摆、岩石、接触阴影分别辨认。仅有模糊暗块不等于额外脚；明确独立的鞋面与鞋底才支持重复鞋形判断。证据不足标待核查，不以“被长袍挡住”作为直接通过理由。
4. 核对脚踝—鞋口衔接和左右脚朝向；脚踝被衣料遮住时只报告可见证据。检查鞋底与承托面接触、落地阴影及重心；步行、抬脚、踏云依动作与神通设定判定。
5. 发现第三只鞋或明确重复鞋底作为阻断问题，修复后重新放大计数，并复查双手、法器和衣摆是否产生新问题。
6. 视频中检查接地—抬脚—再落地的全过程，尤其遮挡后重新露出的脚；禁止鞋形增殖、左右脚互换、鞋底滑移与无动作依据的接触点跳变。抽帧不足以证明全过程正确。

正面约束：每位普通人物的两足关系符合设定，每只鞋一组鞋面与鞋底；衣摆遮挡的残片可归属同一只脚，鞋与衣料、地面分界清楚，接触与支撑合理。

# 长篇多角色项目：资产一致性与生产预算增补 V2.1

## 5. 手足、左右方向与多人动作专项

- 姿态卡先用角色自身解剖左右定义，再记录相机方位和画面左右，三者不能混淆。镜像资产须显式登记。不能写死“所有左手拇指都在画面某一侧”，方向必须结合掌背、前臂旋转及机位判断。
- 每条手臂从对应肩膀逐段追踪到上臂、肘、前臂、腕、掌和五指；核对掌心接触面、拇指对握、肘关节方向与受力。禁止同侧双手、反接手腕、从袖口生出他人的手；合理遮挡不编造错误，无法判断则待核查。
- 脚步逐个检查髋—膝—踝—脚尖方向、鞋面/鞋底、台阶高度、脚底接触、支撑脚与摆动脚、重心和惯性。抬脚是正常动作，不要求两脚同时整掌着地；不得用裙摆、水花或裁切遮住已知错误。
- 牵手、搀扶、推门、扶栏、拄拐分别写接触对象与作用力方向；不能用同一“手握物体”模板代替。推门核铰链与门板转动，扶栏核掌根与栏面，拄拐核支点承重。
- 同一姿态连续返修仍不可靠时，改用能表达同一剧情的简洁动作或机位，例如平掌推门、短步扶栏；记录动作变更及用户要求，不擅自新增剧情。已经批准镜头不得因新专项而自动重生。
- 八仙同框先按BX01—BX08逐人对照母图，八个独立身份、体型、衣服层次、法器、脚步、视线与行进方向全部列明。不得把宽胖汉钟离与瘦老铁拐李画成同体型同衣服。
- 群体离去时，每人头、肩、髋、膝、脚的总体方向与路径一致，允许自然小幅观察；不为展示法器让曹国舅逆行或转向海面。调整错位间距、宽堤机位以提高可辨性，不能复制八人相同走姿。

## 6. 神通实体化与高细节预算

每个效果说明来源—传播介质—作用对象—可见结果—消散过程。优先让法术作用于水、雾、荷瓣、花藤、石面和道具，而非无因铺满光斑。

- 莲瓣与水膜表现承托和净化；葫芦口浊气须有出入口与流向；横笛/鱼鼓以水面可见涟漪表现共振；剑光以切开的潮锁/水层和接触结果表现。焦痕、裂石、燃烧只在剧本允许时出现，不能每次拔剑都添焦痕。
- 法术大场面可用大远景、环境反应、过肩或剪影建立尺度，把面部细节预算放在对话近景；这不是用远景免除一致性检查，身份、人数、道具轮廓、空间和动作因果仍必须通过。
- 高细节与大场面分别验收，不能只提高锐化、饱和度、粒子密度冒充电影质感。源图像素、处理方法与真实输出规格如实记录。

## 7. 场景复用与尺度锚点

- 按现行剧本建5—8个主场景资产组作为规划范围，而非已建成数量。可从渔村/屋内护灯点/海堤与礁路/海底封印/半沉神殿/归墟海门等现有地点归组；蓬莱、龙宫、天庭、修炼洞不因外部示例而自动加入本片。
- 每组有scene_id、拓扑平面、关键视角参考、可用机位、灯位卡、天气/时段、固定建筑、地平线、入口出口、行进轴线、尺度参考物。六视图按空间可用方向采集，缺失方向按需求补，不每场新造同一村庄。
- 用人物、殿门、石柱、浪高等已定义物体建立尺度，记录单位和相对比例；大景人物可小，但不能无理由远近比例突变。
- 灾前/受灾/修复为同场景不同状态版本，破损位置、水位和灯火变化可追踪；不能为方便换掉地形。

## 8. 场次表、镜次预算及真实产能

先锁资产与基线→按批准五幕建立场次表→每场拆完整动作/对白/反应/转场→预算镜头、图片、生成段与续接组→分批生产。五幕结构已定时复用，不重复索要已给信息。

预算表必备：幕/scene_id、故事节拍、目标时长、镜型类别、镜头清单及数量、ASL来源、关键帧数量、Clip数量、Chain数量、平台实际可用时长、重试假设、成本单价出处/时间、出处、置信度、待确认、完成与批准状态。

- 单一镜型可用N≈时长/ASL作预算；混合镜型按类别分别分配时长再求和。先检查镜型总时长是否等于场次时长，四舍五入后调平，并注明只是预算，实际以剪辑为准。
- 108分钟、1200—1700镜、45—65场、约1400镜、450—700段等仅为待校准规划假设，不能作为八仙已确定全片总量或库存缺口。没有全片连续分镜就不能精确宣布“还剩多少全片镜头”。
- 108分钟=6480秒。若每次最长15秒且所有成片素材均来自这些生成段，无损无废片覆盖时长的理论下限为432段；这不是实际产量。修剪、重试、首尾重叠、延展、变速和可复用实拍等必须另列，不能直接承诺450段足够完成。
- 15秒是分段规划上限示例，实际调用受已授权平台、模型、账号可用能力约束；不假定所有工具均能15秒。不得为了凑15秒改变原台词或塞入多个无法验收动作。
- 图片需求=逐镜实际需要的首帧/尾帧/中间控制帧+新增批准参考资产，扣除可复用批准图；失败重试另计。不能一律以1镜=1图或1段=1图计算。
- 样板完成率、资产覆盖率、全片拆镜率、图片批准率、视频可用时长分别报，不能互相替代。

## 9. 长镜续接与音画同步

续接表逐组登记：chain_id、shot_id、clip_id顺序、源首帧/尾帧文件与时间码、重叠窗口、有效入出点、角色/道具/场景末初状态、位置和视线、主光/曝光、海风/粒子方向、相机焦距/位置/运动速度、声音接点、审核状态。

- 后段以已核验的前段末状态承接，不能重新从起势、落地、开门或上升动作开始。过海与斗法按实际剧本列高风险组；天庭等未出现地点不预设为必做组。
- 先正常播放整段与接缝，再慢放动作接触及遮挡，检查位置、衣服、法器、光线和速度；首尾静帧相似不足以证明全段连续。
- 三层声轨与分镜同时规划：环境层（潮、风、雨、空间回响）；动作层（脚步、衣料、门框、拔剑、道具接触）；神话层（有来源的低频、神通、横笛/鱼鼓主题）。龙吟、颂唱等只有剧情需要才用。
- 声音cue记录起止时间码、声音来源、角色/道具ID、距离/混响、强弱、节奏、素材来源和授权状态。剑出鞘音、足音和杖尖音对应实际画面接触；主题音乐不盖住关键动作和对白。

## 首尾控制帧与真实视频衔接
- 控制尾帧是同镜后续状态，按动作必要性生成，不机械要求每镜再画一张；已有获批A/B状态优先复用。切镜接续与同镜插值分别登记。
