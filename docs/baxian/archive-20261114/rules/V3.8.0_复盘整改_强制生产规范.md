# 《星火计划 / 八仙大显神通》V3.8.0｜复盘整改与强制生产门禁

**生效日期：2026-11-12。** 本规则接续 V3.7.1；冲突之处以本规范的“失败即阻断”和资产保护原则为准。适用于任何文本转图、参考图生成、局部编辑、人物分层、群像合成及图生视频。**规则文件不等于生成器已被技术接管。** 接入前必须如实标注未部署。

## 复盘中被禁止的六种操作
1. 只把定妆图写进提示词，未证明图像原件提交至生成器。
2. 用户要求“只换一人”，却用全图重绘或文生图替代局部编辑。
3. G3-S 尚未 PASS 就调用生成接口；出图失败后才补写检查报告。
4. 将过期母图的 Alpha 蒙版套在新图上，未对来源 SHA-256。
5. 仅校验文件哈希，不进行成图的脸/法器/场景/物理关系核验。
6. 把「导演批准」「模型调用成功」「G4视觉合格」「技术锁版」视为同一状态。

## 五道硬门禁（不可绕过）
**G0 资产准入**：每一人物、动物、法器、场景、风格必须用批准的 `asset_id`、不可变原图路径、`sha256`、`approval_id` 锁版；每次编辑与分层使用匹配 SHA 的同一版源图。缺图、冲突、哈希不符 = BLOCK。

**G1 真实引用**：逐个验证接口支持所需参考图数、角色/道具约束、编辑方式、固定模型版本；记录实际 request ID 和输入文件的映射回执，不能只填自述字符串。SDK/模型仅“接受参考图”不意味着身份已锁住。无法验证 = BLOCK。

**G2 编辑范围**：用户要求局部替换时必须具备原底图、限制范围的蒙版/分层、受保护区域清单及不可编辑区域的像素差检查方案。全图重新采样不是局部编辑；若工具不能精确保留其他人，禁止生成替代。不同透视/光照的素材要先以小范围构图方案审定。

**G3-S 生成前放行**：脚本镜号、动作、正负提示、资产、镜头轴线/构图、图像输入、模式与能力、画幅单帧要求、预定G4审查必须全部真实通过。输出只能 `PASS` 或 `BLOCK`。`BLOCK` 不调用模型，不进入下一镜。不得把测试 JSON 中填入虚构的 `PASS` 代替生成器回执。

**G4 生成后核验**：对照**现行**锁定母图检查逐人五官发型、衣服、法器专属关系、数量、手指脚部、接地、运动物理、环境和镜头轴线。局部编辑必须实际计算非编辑区域差异图，并记录容许误差；若要求“其他完全不变”，容许误差应为 0。通过 G4 后另等导演明确批准，再登记最终 SHA-256，才可成为 CURRENT。对压缩/色彩管理差异须显式记录，不得声称逐像素相同。

## 群像专用硬约束
- 8个角色必须来自8份现行批准母图；白驴随BX05同组；玉板/渔鼓/扇/洞箫/花篮/莲台/金属拐杖/葫芦/剑等明确归属。
- 分层先按原始 RGB 不改像素提取，Alpha遮罩来源哈希逐一匹配，逐人验收脸、手脚、法器和边缘；不合格层不能用于正式拼接。
- 先站位图（仅预演）和固定海岸底图，再整合到16:9单张。不得让生图模型同时重新“想象”八张脸。批准预演并不等于批准合成。
- 若只替换汉钟离，仅汉钟离及其大绿扇是允许编辑区域；其他七人、白驴、法器、背景保持原像素；与目标重叠区域须分别分层精修。像素比较FAIL则整张FAIL。

## 状态机（明确区分）
`ASSET_APPROVED` → `REFERENCE_VERIFIED` → `G3S_PASS` → `GENERATED_CANDIDATE` → `G4_PASS` → `DIRECTOR_APPROVED` → `CURRENT_ARCHIVED` → `VIDEO_PREFLIGHT`。
任何失败进入 `BLOCKED`，只能补齐证据后重新审核；不能跳转或自动晋级。每一镜单张交付审查。

## 视频同样适用
必须使用导演批准的关键帧和真实输入回执，固定动作范围、相机方向与场景。短段建议2–4秒，最长时长由模型支持情况和项目风险评估确定，不能假称统一的6秒物理上限。先完成图生视频门禁再请求生成，成片要查脸/服装/法器/空间/镜头/物理时序漂移。失败不能自动发布。

## 测试与部署边界
附带 `verify_gate.py` 和反例测试属于**离线失败即阻断校验**。它们可验证本地源图、SHA、必要字段与明示的流程证据，但不能单凭文字 JSON 判定模型真实支持遮罩、真实保存未编辑像素或自动视觉识别零失误。实现生产硬阻断需将所有模型调用统一经过门禁服务；提供商接口收据须独立可验证，G4必须有真实像素/人工审查。
