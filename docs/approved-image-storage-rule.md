## 触发与范围

用户针对明确图片或明确整批图片说“过”“通过”“过，存”“这些先过”即触发。只保存被批准的确切版本，不把相似图、修补版、其他候选自动视为通过。明确采用某组图片并指定剧情用途时，保存该组原件并记录原话与范围。范围不清时，先保存已明确通过的图片，再澄清剩余图片。

## 必须当轮完成

1. 锁定原图字节，记录文件名、项目、章节/镜头、版本、批准依据、批准时间及来源文件 ID。不得以缩略图、预览图或重生图替换原件。
2. 计算 SHA-256，记录实际像素与文件大小。用 SHA-256 去重；同名不同内容保留独立版本，不覆盖旧图。
3. 立即上传 Google Drive 项目归档位置。当前八仙项目根目录：`1INUBxoXs538im-35ZnHvGmjP-Fxih5ua`。命名建议：`项目_镜头_内容_版本_日期.png`；保留原始文件名映射。单张获批即保存，不等整批凑齐、当天结束或视频生成完成。
4. 核验上传回执，并读取远端元数据，确认文件 ID、大小和目标父目录；服务提供校验值时与本地比对。记录可打开的云盘链接。上传失败保持 `PENDING_UPLOAD` 或 `UPLOAD_FAILED`，保留原件及失败原因；仅在实际上传并核验后标记 `ARCHIVED_VERIFIED`。
5. 同步 GitHub 归档分支：清单、批准依据、哈希、像素、云盘文件 ID/链接与必要的原图副本。当前仓库：`huuchaujfj102-beep/5588a`。未经检查不得直接合并 main；大量素材按日期目录组织，超过平台限制时采用分卷或现有大文件机制并记录位置。
6. 回复本轮保存数量与云盘/GitHub链接。逐个检查结果，部分成功必须分别说明，不把“已写入聊天/已在文件库”当作“已上传 Google Drive”。

## 状态与版本保护

- `APPROVED_LOCKED`：用户已批准画面，禁止擅自重绘或替换。
- `ARCHIVED_VERIFIED`：对应存储目标已有成功回执且完成核验；云盘与 GitHub 分别记录状态。
- 导演画面批准、静态技术审核、视频动态验收分别记录；图片通过不等于视频已通过，也不等于原生8K。
- 被否决/被替换的历史版本不得列入当前通过清单；保留历史文件，不擅自删除。
- 批次打包必须附清单、原图及批准记录；汇总包不替代后续单张即时保存。
- 当前规则是执行约定与仓库入口指引，不声称已经部署全天候后台监听。每次相关制作任务开始时读取本规则，获得通过指令后当轮执行；未运行的会话不会自行上传。
